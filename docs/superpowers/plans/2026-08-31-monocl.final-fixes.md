# MonoCl final-review fixes

The final whole-branch review found nine findings: three Important
behavioural defects and six Minor. This document specifies the single
fix wave. It is written against `docs/superpowers/specs/2026-08-31-monocl-design.md`,
which has already been corrected (commit `41cae25`) and remains the
binding authority.

All three Important findings are defects where the CODE contradicts the
spec. The spec already said the right thing in each case, so these are
not design changes — they are the code catching up.

---

## Fix 1 — a failed poll must not destroy the cached reading

**Where:** `MonoCl/IndicatorStore.swift`, `apply(_ outcome: UsageOutcome)`
and `apply(_ outcome: StatusOutcome)`.

Today every failure nils the samples. The spec's failure table lists
`.unknown` for eight of ten rows — but NOT for network/timeout ("keep
last reading until `staleAfter`") and NOT for 429. So the retain/clear
split is a transcription of that column, not a judgement:

| Failure | Sample |
|---|---|
| `.offline`, `.rateLimited` | **retained** |
| `.credentialsNotFound`, `.keychainDenied`, `.keychainUnavailable`, `.credentialsUnreadable`, `.tokenExpired`, `.authorizationRejected`, `.accessRefused`, `.unexpectedResponse` | cleared |

`StatusFailure.offline` retains; `.unexpectedResponse` clears.

Why it matters twice over. A dropped packet currently greys all three
dots for a minute and back — the flicker the spec says "teaches the user
to ignore it". And because samples are nil'd on failure, `isTrusted`'s
age branch can only fire when `refreshInterval > staleAfter`, reachable
only by hand-configuring 600 s against 60 s. In the default
configuration Task 3's age budget is dead code.

### 1a — `Reading` gains `note`

```swift
public struct Reading: Sendable, Equatable {
    public let state: IndicatorState
    public let detail: String
    /// Why this value may be ageing.  Nil normally.
    public let note: String?
    public let asOf: Date
}
```

Update `Reading.unknown(detail:asOf:)` to pass `note: nil`, and add the
`note` argument to the full initialiser. Every existing call site must
compile; prefer a defaulted `note: String? = nil` on the initialiser so
the unknown path and the tests need no churn.

In `usageReading`, the TRUSTED branch sets `note: usageFailure?.menuText`.
The `.unknown` branches leave it nil — their `detail` already carries the
reason. Same shape in `platformReading` with `statusFailure`.

**Do not compose a joined string in the store.** The store emits atoms
(`"62%"`, `"Offline"`); each surface joins in its own style. A store-side
`" · Offline"` would put separator style in two places and produce
`"62% · Offline · resets 14:20"` with neither surface in control.

**Do not** add a `.stale` case to `IndicatorState` — it would force a
colour decision and collide with "colour means the user's usage is high".

**Do not** infer "MonoCl has a problem" from `usageFailure != nil`
anywhere: after this fix it no longer implies unknown.

### 1b — the surfaces render the note

`TooltipComposer.line`: when `reading.note` is non-nil on a known
reading, append it in the composer's own style, after the reset time.
`MenuBuilder.menu`: likewise in its own style. Both must still show the
percentage — a retained number annotated as possibly ageing is the point.

### 1c — the test that currently pins the contrary behaviour

`MonoClTests/IndicatorStoreTests.swift`, "Failures never produce color",
asserts `.offline` blanks immediately. Replace it with ONE parameterised
test over every `UsageFailure` case, so the retain/clear split itself is
the pinned contract and a future case must be classified rather than
defaulting:

```swift
@Test("Every failure either retains the sample or clears it, by case", arguments: [
    (UsageFailure.offline, true),
    (UsageFailure.rateLimited(retryAfter: nil), true),
    (UsageFailure.credentialsNotFound, false),
    (UsageFailure.keychainDenied, false),
    (UsageFailure.keychainUnavailable, false),
    (UsageFailure.credentialsUnreadable, false),
    (UsageFailure.tokenExpired, false),
    (UsageFailure.authorizationRejected, false),
    (UsageFailure.accessRefused, false),
    (UsageFailure.unexpectedResponse, false),
])
func failureRetainsOrClears(failure: UsageFailure, retains: Bool) {
    let s = store()
    s.apply(samples(session: 95))
    s.revalidate(now: now)
    #expect(s.session.state == .critical)

    s.apply(UsageOutcome.failure(failure))
    s.revalidate(now: now)

    if retains {
        // The value stands, annotated with why it may be ageing.
        #expect(s.session.state == .critical)
        #expect(s.session.detail == "95%")
        #expect(s.session.note == failure.menuText)
    } else {
        #expect(s.session.state == .unknown)
        #expect(s.session.detail == failure.menuText)
        #expect(s.session.note == nil)
    }
}
```

Keep a separate, narrower test asserting the governing rule the original
one was named for — that NO failure yields `.warning` or `.critical`
*as a consequence of the failure*. With retention that now reads: a
cleared failure yields `.unknown`, and a retained one yields whatever
the sample's own threshold state was, never a state the failure chose.

## Fix 2 — the spec's "menu open" refresh trigger exists nowhere

**Where:** `MonoCl/AppDelegate.swift`.

§Refresh and staleness names four triggers: app launch, **menu open**,
wake, and explicit Refresh now. The first, third and fourth exist. The
menu is assigned with no `NSMenuDelegate`, so opening it calls back into
nothing.

Make `AppDelegate` conform to `NSMenuDelegate`, set itself as the menu's
delegate, and implement:

```swift
    func menuNeedsUpdate(_ menu: NSMenu) {
        // Re-render before the menu is shown: the held reading may have
        // crossed its staleness budget since the last poll, whose cadence
        // stretches to the backoff cap.
        render()
        usageRefresher?.refreshNow()
        statusRefresher?.refreshNow()
    }
```

`render()` rebuilds the menu, so take care not to recurse: rebuild the
menu's ITEMS from the delegate rather than reassigning `statusItem.menu`
inside `menuNeedsUpdate`. If that proves awkward, split `render()` into
`renderIcon()` and `renderMenu()` and call only what is needed.

## Fix 3 — a malformed keychain record is not an endpoint problem

**Where:** `Packages/ClaudeUsage/Sources/ClaudeUsage/UsageSource.swift`.

`CredentialError.malformed` currently maps to `.unexpectedResponse`, so
a credential file that failed to decode tells the user the endpoint
misbehaved. Add a case and map it:

```swift
    /// The stored credential could not be decoded.  The fault is local,
    /// so it is not reported as an endpoint problem, and it is sticky:
    /// Claude Code will not rewrite the record in response to MonoCl
    /// polling it, so retrying to the backoff cap achieves nothing.
    case credentialsUnreadable
```

`menuText`: `"Claude Code credentials unreadable"`.
`stopsPolling`: **true**.
Mapping: `case .malformed: return .failure(.credentialsUnreadable)`.

### 3a — `stopsPolling` becomes exhaustive

This lands here because a `default:` arm is exactly what would have
silently misclassified the new case:

```swift
    public var stopsPolling: Bool {
        switch self {
        case .credentialsNotFound, .keychainDenied, .credentialsUnreadable:
            true
        case .keychainUnavailable, .tokenExpired, .offline,
             .authorizationRejected, .accessRefused, .rateLimited,
             .unexpectedResponse:
            false
        }
    }
```

No `default`. Adding a case must fail to compile until someone decides
whether it is sticky.

Extend the existing `stopsPolling` test to assert all ten cases.

## Fix 4 — revalidate when trust expires, not only when a poll lands

With Fix 1 retaining samples, a retained value can outlive the poll that
produced it, and the poll cadence stretches to the 15-minute cap. A dot
showing amber for a reading the staleness rule would reject is exactly
what the colour rule exists to prevent. Fix 2 covers the tooltip and
menu, but not the dot while nobody has the menu open.

### 4a — `Indicators` gains `trustExpiry`, and `isTrusted` is re-expressed

This is subtractive: it removes the duplicated comparison rather than
adding a second mechanism.

```swift
/// The instant this sample stops being trustworthy: the earliest of its
/// age budget, the credential's expiry and the window's reset.
///
/// Non-optional deliberately.  `staleAfter` always bounds the result, so
/// there is no "nothing constrains it" case for a caller to branch on.
public func trustExpiry(_ i: TrustInputs) -> Date {
    min(
        i.asOf.addingTimeInterval(i.staleAfter),
        i.tokenExpiresAt ?? .distantFuture,
        i.windowResetsAt ?? .distantFuture
    )
}

public func isTrusted(_ i: TrustInputs) -> Bool {
    trustExpiry(i) > i.now
}
```

The existing `StalenessTests` must all still pass unchanged — that is
the evidence this refactor preserves behaviour. Add cases asserting
`trustExpiry` returns the earliest of the three, once for each of the
three being the minimum.

### 4b — one self-cancelling timer in `AppDelegate`

```swift
    private var expiryTask: Task<Void, Never>?
```

At the END of `render()`, cancel and re-arm it: compute the earliest
`trustExpiry` across the readings that are currently trusted; if one
exists and is in the future, sleep until it and call `render()` once.

It must be independent of the fetch cadence. Do NOT fold this into
`Refresher` and do NOT cap `Refresher`'s sleep at `staleAfter` — that
would defeat the backoff, whose purpose is to stop hammering an endpoint
that returned 403 or 429.

## Fix 5 — remove the redundant stroke assignment

`MonoCl/MenuBarIcon.swift`, `draw(_:in:)`, the `.ring` case: delete the
`if faint { ... setStroke() }` line. The tint already carries the
dimming, so the second assignment is a no-op that only holds because
`iconSpec` always pairs `.ring(faint: true)` with `.dimmed`.

Leave the `faint:` Bool itself alone. Removing that duplication properly
touches `IconSpec`, its tests and the renderer across two packages to
eliminate something that causes no defect.

## Fix 6 — thread the clock through the tooltip formatter

`MonoCl/TooltipComposer.swift`: `format` chooses `HH:mm` versus
`EEE HH:mm` from `date.timeIntervalSinceNow`, reading the real clock
inside a function that otherwise injects its timezone. Add
`now: Date = .now` to `tooltip(...)` and thread it to `format`, comparing
against the injected value.

Then assert the `EEE HH:mm` branch's output — currently the branch is
exercised but its string never checked. That closes a second parked
minor for free.

## Fix 7 — remove an unused package dependency

`Packages/ClaudeUsage/Package.swift`: the dependency on `Indicators` is
unused (`grep -rn "Indicators" Packages/ClaudeUsage/Sources Packages/ClaudeUsage/Tests`
returns nothing). It is a dead edge left by the plan's justified move away
from sources returning `[Reading]`. Remove both the package-level entry
and the target-level product. `PlatformStatus`'s dependency is real —
leave it.

## Fix 8 — assert the outbound request's headers

`Packages/ClaudeUsage/Tests/ClaudeUsageTests/Fakes.swift`: `FakeHTTP`
accepts `headers` and discards them. The endpoint contract makes two
positive claims about the request that nothing asserts — the bearer token
is present, and `anthropic-beta` is absent. Re-adding the beta header or
dropping the bearer currently passes green.

Record the headers on the fake, and assert in the success test:

```swift
    #expect(http.lastHeaders?["Authorization"] == "Bearer t")
    #expect(http.lastHeaders?["anthropic-beta"] == nil)
```

## Fix 9 — test the `Refresher` state machine

The spec's Testing table promises "Refresh state machine | Fake source,
network carve-out" and nothing tests it. Every collaborator is already
an injected closure, so this needs no new seam.

Add `MonoClTests/RefresherTests.swift` covering: consecutive failures
accumulate and lengthen the interval; a success resets the count;
`refreshNow()` clears the count; `stop()` cancels. Inject a fast base
interval so the tests do not sleep for real seconds, and assert on
observed tick counts rather than wall-clock timing — a timing-sensitive
test is a flaky test.

---

## Fix 10 — remove an unchecked cross-module assumption

`MonoCl/MenuBarIcon.swift`, `accessibilityDescription(for:)`: indexes
`names[0]`, `[1]`, `[2]` unconditionally, inside a type whose geometry
code is written generically for any dot count. The three-dot guarantee
lives in `IndicatorStore.states`, a different file in a different module,
enforced by nothing. Unreachable today; a two-dot spec crashes the app.

Zip the names against a label array, or build the description from the
pairs, so no index can be out of range.

  rather than inferred from `exit=0` — a stale project reports

  returns 0.
